## ממצאים

### F1 — Critical: `GET /v1/tasks` מחזיר את `passwordHash` (bcrypt) של המשתמש המשויך לכל משתמש מחובר, כולל FIELD
- שחזור:
  ```
  curl -s "$A/tasks?take=1" -H 'X-Tenant: qa-a' -H "Authorization: Bearer $TOK_F1" | jq '.items[0].assignedTo | keys, .passwordHash[0:7]'
  ```
- צפוי: `assignedTo` עם `id, name` בלבד (כמו `findOne`).
- בפועל: `id,tenantId,email,passwordHash,name,role,isActive,skills,homeLat,homeLng,mustChangePassword,lastLoginAt,…`, ו-`passwordHash` מתחיל ב-`$2b$12$`.
- מקור: `src/modules/tasks/tasks.service.ts:81` — `include: { customer: true, assignedTo: true }`. קיים גם ב-main, אבל כל טכנאי יכול לאסוף hash של כל עמית (ושל OWNER/MANAGER כשהם משויכים) ולפצח אופליין, וגם כתובת הבית (`homeLat/homeLng`).

### F2 — High: טכנאי (FIELD) קורא, רואה ברשימה וסוגר משימה שלא שויכה אליו
- שחזור (`$T2` משויכת ל-`qa-field-a2`; הטוקן של `qa-field-a1`):
  ```
  curl -s $A/tasks/$T2 -H 'X-Tenant: qa-a' -H "Authorization: Bearer $TOK_F1"        # 200 + customer.phone/address/email
  curl -s $A/tasks     -H 'X-Tenant: qa-a' -H "Authorization: Bearer $TOK_F1"        # 200, משימות של a1 ושל a2
  curl -s -X POST $A/tasks/$T2/close -H 'X-Tenant: qa-a' -H "Authorization: Bearer $TOK_F1" \
       -H 'Content-Type: application/json' -d '{"checklist":[{"label":"התקנה","done":true,"priceCode":"INSTALL"}]}'
  # → 201 {"status":"CLOSED","alreadyClosed":false}
  ```
- צפוי: 404, כמו `share-link`/`on-the-way` על אותה משימה (שם `findForActor` מסנן לפי `assignedToUserId`, ואכן מחזיר 404).
- בפועל: 200/201. טכנאי סוגר עבודה של אחר עם צ'קליסט שרירותי → שורות `done:true` נכנסות לחשבונית ולהכנסה המשוערת בדו"ח הרווחיות, מלאי מנוכה, `equipment.lastServicedAt` מתעדכן.
- מקור: `src/modules/tasks/tasks.controller.ts:25-47` (`@AnyRole` בלי העברת תפקיד), `tasks.service.ts:108` (`findOne`) ו-`:290` (`close`) — אין סינון לפי actor.

### F3 — High: ה-throttle ה"הדוק" של כל הנתיבים הציבוריים לא נאכף
- שחזור:
  ```
  for i in $(seq 1 12); do curl -s -o /dev/null -w '%{http_code} ' -X POST $A/public/status/<tok>/confirm; done
  # בפועל: 201 ×12 (הצפוי: 429 מהבקשה השישית, limit 5/min)
  for i in $(seq 1 40); do curl -s -o /dev/null -w '%{http_code} ' $A/public/status/$(openssl rand -base64 32 | tr '+/' '-_' | tr -d '='); done
  # בפועל: 404 ×40 (הצפוי: 429 אחרי 30)
  curl -s -D - -o /dev/null -X POST $A/public/status/<tok>/confirm | grep -i ratelimit
  # רק X-RateLimit-*-short:20 / medium:200 / long:2000 — המגבלות הגלובליות
  ```
- סיבה: `ThrottlerModule.forRoot` מגדיר throttlers בשמות `short/medium/long` (`src/app.module.ts:100-104`), והקונטרולרים הציבוריים מגדירים override בשם `default`, שלא קיים — ולכן הוא מתעלם בשקט. `AUTH_THROTTLE` (`auth.controller.ts:20`) עושה את זה נכון.
- מיקומים: `task-status.controller.ts:46,52,58`, `equipment.controller.ts:56,62`, `quotes.controller.ts:46,52`.
- השפעה: עד 200 כתיבות/דקה/IP לא מאומתות (אישור, בקשת מועד, אישור/דחיית הצעה) — כל אחת כותבת `audit_logs` (ראו F16); ה-spec (סעיף "קישורים") מחייב throttle הדוק.

### F4 — Medium: קלט ציבורי פשוט מפיל את השרת ל-500 (לפני אימות, ובפיתוח חושף נתיבי קבצים ושאילתת Prisma)

- 404 אחיד לטוקן שבור (קצר, ארוך, תווים לא חוקיים, `' OR 1=1 --`, 5000 תווים), לא קיים, פג (`expiresAt` בעבר), בוטל (שיתוף חוזר / שליחה חוזרת של הצעה), ומטרה אחרת (טוקן סטטוס על booking/quote ולהפך).

- אישור/בקשת מועד על משימה סגורה → 409. `on-the-way` על סגורה → 409.
