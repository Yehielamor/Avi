# מערכת העיצוב

מסמך מחייב לכל קוד UI.

**מקור האמת הוא `frontend-web/src/styles/theme.css`.** המסמך הזה מסביר *למה*.

---

## שלוש החלטות שמכתיבות את כל השאר

### 1. RTL-first, לא RTL-בדיעבד

הממשק עברי. כל המרווחים והיישור משתמשים ב-**logical properties**:

| ❌ פיזי | ✅ לוגי |
|---|---|
| `ml-2` / `mr-2` | `ms-2` / `me-2` |
| `left-3` / `right-3` | `start-3` / `end-3` |
| `text-left` | `text-start` |
| `border-l` | `border-s` |
| `rounded-l-md` | `rounded-s-md` |

`dir="rtl"` על ה-`<html>` ב-`index.html` הוא המתג היחיד. Tailwind v4 מייצר
את הכיוון הנכון אוטומטית — **אין CSS כפול לכל כיוון, ואין `[dir=rtl]` overrides.**

זה גם מה שיהפוך תמיכה באנגלית בעתיד לשינוי של תכונה אחת.

#### מה נשאר LTR

מספרים, אימיילים, כתובות URL ומזהים — גם בתוך משפט עברי. בלי זה,
הסימנים (`@`, `+`, `-`) קופצים לצד הלא נכון:

```tsx
<span className="ltr-inline">{customer.email}</span>
```

שדות `type="email" | "tel" | "url" | "number"` מקבלים את זה אוטומטית
ב-`<Input>`.

### 2. הצבע נבחר לשטח

המשתמש הוא טכנאי שמסתכל על טלפון תחת שמש ישראלית, לא מעצב מול מסך מכויל.

- **ניגודיות גבוהה**, מעבר לרף WCAG AA.
- **מצבי סטטוס נבדלים גם בצורה.** לכל `Badge` יש רקע, גבול **ונקודה** — לא
  גוון בלבד. כ-8% מהגברים הם עיוורי צבעים, וגוונים שטוחים באור חזק נראים דומים.
- **אזורי מגע 44px לפחות.** `Button size="md"` הוא `h-11`. טכנאי מפעיל את זה בכפפות.

הצבעים מוגדרים ב-**OKLCH** ולא ב-hex: בהירות תפיסתית אחידה בין גוונים. ב-hex,
`#0066cc` ו-`#00cc66` באותה "בהירות" מספרית נראים שונים לחלוטין.

### 3. טוקנים סמנטיים, לא ליטרליים

```tsx
<div className="bg-surface-raised text-fg border-border">   {/* ✅ */}
<div className="bg-slate-800 text-slate-100 border-slate-700"> {/* ❌ */}
```

הקוד אומר *מה התפקיד*, לא *מה הגוון*. שלוש תוצאות:

1. מצב כהה עובד בלי לגעת באף רכיב.
2. `TenantConfig.theme` — ערכת נושא לכל טננט — היא החלפת משתני CSS בלבד.
3. שינוי גוון המותג נוגע בקובץ אחד.

## סולם המשטחים

מהעמוק לגבוה. עומק נבנה מהיררכיית משטחים, לא מצללים.

| טוקן | שימוש |
|---|---|
| `canvas` | רקע הדף |
| `surface-sunken` | שקעים — כותרות טבלה, מצבי skeleton |
| `surface` | סרגל צד, כותרת עליונה |
| `surface-raised` | כרטיסים, חלוניות |
| `surface-hover` | מצב ריחוף |

**המצב הכהה אינו היפוך.** הוא בנוי בנפרד: המשטחים מקבלים גוון כחלחל קר,
והגוונים מוחזרים לרוויה גבוהה יותר כדי לשמור על אותה נראות בבהירות נמוכה.
היפוך אלגוריתמי מייצר צבעים בוציים ומצבי סטטוס שמאבדים הבחנה.

## טיפוגרפיה

**Heebo** — עברית ולטינית באותה משפחה, עם משקלים אמיתיים. ערבוב גופן עברי
עם fallback לטיני מייצר קפיצות בגובה השורה בתוך אותה פסקה.

`font-synthesis-weight: none` — אוסר על הדפדפן לזייף מודגש. Heebo מספק את
המשקלים בפועל, וזיוף פוגע בקריאות של עברית במיוחד.

**גובה שורה 1.65 ולא 1.5.** לעברית אין אותיות גדולות, ולכן גושי טקסט נקראים
צפופים יותר באותו ערך מספרי.

### מספרים

```tsx
<td className="tabular">{formatCurrency(invoice.totalAmount)}</td>
```

`font-variant-numeric: tabular-nums` — ספרות ברוחב שווה. **חובה בכל תצוגת
כסף או כמות בטבלה**, אחרת העמודות לא מתיישרות והמספרים "רוקדים" בזמן רענון.

---

## כסף — מחרוזת, לא מספר

```tsx
formatCurrency(invoice.totalAmount)   // totalAmount הוא string
```

השרת מסרלז `Decimal(12,2)` **כמחרוזת**. `JSON.parse` היה הופך אותו ל-double
של JS, עם שגיאת עיגול בינארית — בדיוק הבאג שנמצא בצד השרת.
כל העיצוב עובר דרך `formatCurrency` ב-`lib/utils.ts`.

## זמנים

השרת שולח UTC. התצוגה **תמיד בשעון ישראל, מפורשות** — לא לפי שעון הדפדפן:
מנהל שנוסע לחו"ל צריך לראות את אותן שעות שהטכנאי בשטח רואה.

```tsx
formatDateTime(task.createdAt)   // 14/09/2026 20:30
formatRelative(task.createdAt)   // "לפני 3 שעות"
```

`formatRelative` נופל לתאריך מלא מעבר לשבוע — "לפני 43 ימים" אינו קריא.

## נגישות

לא תוספת. הדברים הבאים אינם נתונים לשיקול דעת:

| | |
|---|---|
| **פוקוס** | `:focus-visible` עם טבעת של 2px. **לעולם לא `outline: none`.** מוצג בניווט מקלדת בלבד. |
| **דילוג לתוכן** | הדבר הראשון ב-tab order ב-`AppShell`. |
| **שגיאות** | `role="alert"` — קורא מסך מכריז מיד. |
| **טעינה** | `aria-busy` על כפתורים; skeleton ולא ספינר בלבד. |
| **טבלאות** | `<caption className="sr-only">`, `<th scope="col">`. |
| **אייקונים** | `aria-hidden` תמיד. אייקון לבדו מקבל `aria-label`. |
| **ניווט** | `aria-current="page"` על הפריט הפעיל. |
| **תנועה** | `prefers-reduced-motion` מכובד גלובלית. |

## תנועה

עקומות קצרות ומכוונות. זה ממשק עבודה, לא אתר תדמית.

| טוקן | ערך | שימוש |
|---|---|---|
| `--duration-fast` | 120ms | ריחוף, פוקוס, שינויי צבע |
| `--duration-base` | 200ms | חלוניות, מגירות |
| `--duration-slow` | 320ms | מעברי מסך |

לכפתורים `active:scale-[0.98]` — משוב מגע מיידי, חשוב במובייל.

## מצבים — כל ארבעתם, תמיד

כל מסך שטוען נתונים מטפל בארבעה מצבים. **אין יוצא מן הכלל.**

```tsx
{q.isLoading   ? <Skeleton… />
 : q.isError   ? <ErrorState error={q.error} onRetry={() => void q.refetch()} />
 : empty       ? <EmptyState icon={…} title={…} description={…} />
 :               <RealContent … />}
```

- **Skeleton, לא ספינר.** משמר את פריסת הדף ומונע קפיצה.
- **`EmptyState` אומר למה ריק ומה לעשות.** "אין נתונים" לבדו משאיר את
  המשתמש תקוע.
- **`ErrorState` מבדיל בין שגיאה שניתן לנסות שוב לבין כזו שלא.** הצעת
  "נסה שוב" על 403 היא שקר.

## אבטחה בצד הלקוח

**בדיקת הרשאה בקליינט אינה גבול אבטחה.**

```tsx
{can('OWNER', 'MANAGER') && <Button>הפק חשבונית</Button>}
```

זו **הסתרת UI בלבד**. ההרשאה נאכפת בשרת ב-`RolesGuard`, על כל בקשה.
הסתרת כפתור לא מונעת מאף אחד לשלוח את הבקשה.

אותו דבר ל-`beforeLoad` בראוטר: הוא בודק אם קיים טוקן, לא אם הוא תקף.
תקפות נבדקת בשרת.

### אחסון הטוקן

ב-`sessionStorage` ולא ב-`localStorage`. XSS מגיע לשניהם, אבל `sessionStorage`
לא שורד סגירת טאב ולא משותף בין טאבים, מה שמצמצם את חלון הזמן.

**הפתרון הנכון הוא cookie מסוג `HttpOnly` + `SameSite=Strict`**, שאינו נגיש
ל-JS כלל. זה מסומן כשלב הבא — הוא דורש שינוי בצד השרת.

## אימות תשובות מהשרת

כל תשובה עוברת סכמת Zod ב-`lib/schemas.ts`:

```ts
const tasks = await request('/tasks', { schema: taskListSchema });
```

טיפוס TypeScript לבדו הוא הבטחה בזמן קומפילציה על נתונים שמגיעים בזמן ריצה.
שינוי בשרת שלא סונכרן ייתפס כאן, עם הודעה ברורה — ולא כ-`undefined is not an
object` שלושה רכיבים למטה.
