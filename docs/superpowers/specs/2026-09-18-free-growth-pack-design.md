# חבילת צמיחה ללא עלות — תכנון

> 18.09.2026. חמישה פיצ'רים שלא עולים לנו כסף עכשיו: בלי API בתשלום ובלי אישור חיצוני.
> מקדימים את [שלב 1 במפת הדרכים](../../40-growth-roadmap.md) לבקשת בעל המוצר.

## העיקרון: WhatsApp בלי API

קישור `https://wa.me/<מספר>?text=<הודעה>` פותח את ה-WhatsApp **של הטכנאי** עם הודעה מוכנה. הוא
לוחץ "שלח". בלי Meta, בלי עלות, בלי המתנה. כשאישור Meta יגיע (שלב 3 במפת הדרכים) מחליפים את
הכפתור בשליחה אוטומטית; הקישורים והדפים נשארים.

## יסוד משותף

### מועד ביקור
`Task.scheduledStart`, `Task.scheduledEnd` (Timestamptz, nullable). נקבעים ע"י OWNER/MANAGER
במסך המשימה. בלעדיהם דף הסטטוס לא יודע לומר "מתי".

### קישור ציבורי ללקוח
טבלה `PublicLink`: `id`, `tenantId`, `tokenHash` (SHA-256, ייחודי), `purpose`
(`TASK_STATUS` | `BOOKING` | `QUOTE`), `taskId?`, `customerId`, `quoteId?`, `expiresAt`,
`revokedAt?`, `createdAt`.

- הטוקן: 32 בתים אקראיים, base64url. **נשמר רק ה-hash** — דליפת DB לא נותנת קישורים פעילים.
- תוקף: סטטוס — 30 יום; קביעת מועד — 14 יום; הצעת מחיר — 30 יום.
- ה-endpoints הציבוריים: `@Public()` + `@Throttle` הדוק. הטוקן **הוא** ההרשאה, והוא נפתר
  לטננט דרך פונקציית `SECURITY DEFINER` צרה (כמו `resolve_tenant_by_subdomain`), ומשם הכול
  רץ ב-`forTenant` רגיל תחת RLS.
- הדף הציבורי מציג **מינימום**: שם העסק, תיאור העבודה, מועד, שם פרטי של הטכנאי, סטטוס. לא
  כתובת מלאה, לא טלפון, לא היסטוריה. (תיקון 13: צמצום מידע.)
- כל פעולה ציבורית נרשמת ב-`AuditLog` עם `userId = null` ו-`metadata.via = 'public_link'`.

### נרמול טלפון ו-wa.me
`toWaNumber(phone)`: `050-1234567` / `+972 50 123 4567` / `0501234567` → `972501234567`.
מספר שאינו ישראלי תקין → `null`, והכפתור מוסתר (לא נשלח קישור שבור).

### דפים ציבוריים בממשק
`/c/:token` ב-`frontend-web`, מחוץ ל-`protectedRoute`, בלי התחברות. RTL, מובייל קודם.

## 1. דף סטטוס ללקוח

- במסך המשימה (OWNER/MANAGER) וב-PWA (טכנאי): כפתור "שליחה ללקוח ב-WhatsApp" → יוצר (או
  ממחזר) קישור `TASK_STATUS` → פותח `wa.me` עם הודעה בעברית וקישור.
- הלקוח רואה: סטטוס (התקבלה / נקבע מועד / בדרך / הושלמה), מועד, שם הטכנאי.
- פעולות: **"מאשר את המועד"** → `Task.customerConfirmedAt`; **"צריך מועד אחר"** + הערה
  חופשית עד 500 תווים → `Task.rescheduleRequest` + סימון בולט במסך המשימה ובלוח.
- "בדרך": כפתור לטכנאי ב-PWA → `Task.onTheWayAt` (נגזר ממנו הסטטוס).

## 2. ציוד ותחזוקה מונעת

- מודל `Equipment`: `customerId`, `kind` (טקסט: "מזגן עילי"), `model?`, `location?` ("סלון"),
  `serviceIntervalMonths` (ברירת מחדל 6), `lastServicedAt?`, `isActive`.
- `Task.equipmentId?`. בסגירת משימה עם ציוד → `lastServicedAt = closedAt`, באותה טרנזקציה.
- מסך "מגיע לטיפול" (OWNER/MANAGER): ציוד שבו `lastServicedAt + interval <= היום + 14 יום`,
  או שלא טופל מעולם ונוצר לפני יותר מ-interval. ממוין לפי איחור.
- לכל שורה: "שליחת תזכורת" → קישור `BOOKING` + `wa.me`. נרשם `Equipment.lastReminderAt`,
  ושורה שקיבלה תזכורת ב-14 הימים האחרונים מסומנת — לא שולחים פעמיים בטעות.
- הלקוח בקישור בוחר **3 חלונות מועדפים** (תאריך + בוקר/צהריים/ערב) → נוצרת משימה `NEW`,
  `source = CUSTOMER_LINK`, מקושרת לציוד, עם החלונות בתיאור. הקישור נסגר לשימוש חוזר.

## 3. הצעת מחיר

- מודלים `Quote` (`customerId`, `quoteNumber` רץ לטננט, `status`: DRAFT/SENT/APPROVED/DECLINED/
  EXPIRED, `validUntil`, `notes?`, `totalAmount` Decimal, `approvedAt?`, `taskId?`) ו-
  `QuoteLine` (`priceCode`, `description`, `qty`, `unitPrice`, `amount` — **עותק** מהמחירון
  ברגע ההצעה, כמו בחשבונית).
- יצירה מהמחירון בלבד (אותו כלל כמו חשבונית: אין שורה בלי קוד קיים). סכומים ב-`Prisma.Decimal`.
- PDF עברי ("הצעת מחיר מס' N") — ממחזר את `invoice-pdf.util` ו-`hebrew-text.util`.
- שליחה → קישור `QUOTE` + `wa.me`. הלקוח רואה שורות וסכום, לוחץ **"מאשר"** או **"לא עכשיו"**.
- אישור → משימה `NEW`, `source = QUOTE`, צ'קליסט = שורות ההצעה (label, priceCode, qty),
  באותה טרנזקציה. אישור כפול → אותה משימה (אידמפוטנטי ב-DB: `Quote.taskId` ייחודי).
- הצעה שפג תוקפה לא ניתנת לאישור.

## 4. רווחיות

- `InventoryItem.unitCost` (Decimal, nullable). `unitPrice` הקיים נשאר מחיר מכירה.
- דו"ח לתקופה (OWNER/MANAGER): לכל משימה סגורה — הכנסה (סכום שורות החשבונית שלה), עלות חלקים
  (Σ תנועות `TASK_CONSUMPTION` × `unitCost`), רווח גולמי. מקובץ לפי סוג עבודה, טכנאי, לקוח.
- **חלק בלי עלות → הרווח מסומן "חלקי", לא מחושב כאילו העלות אפס.** הדו"ח מציג כמה פריטים חסרי
  עלות, עם קישור לעדכן.
- משימה סגורה שעוד לא חויבה → הכנסה משוערת מהצ'קליסט לפי המחירון הנוכחי, מסומנת "משוער".
- ללא עלות עבודה (שעות) — אין לנו נתון. נאמר במפורש בדו"ח.

## 5. מסלול יומי + Waze

- מסך "היום שלי" ב-PWA: המשימות של הטכנאי לתאריך, לפי `scheduledStart`; משימות בלי מועד
  בסוף.
- כפתור ניווט: `https://waze.com/ul?ll=<lat>,<lng>&navigate=yes` כשיש קואורדינטות, אחרת
  `https://waze.com/ul?q=<כתובת>&navigate=yes`. חינם, ללא API.
- **לימוד מיקומים:** בסגירת משימה ה-PWA שולח (אם הטכנאי אישר מיקום) את מיקום הטלפון; אם ללקוח
  אין קואורדינטות והדיוק < 100 מ' → נשמרות ל-`Customer.lat/lng`. אף פעם לא דורסים קיימות.
- סידור אופטימלי: משימות ללא מועד מסודרות ב-nearest-neighbor מהמשימה הקודמת (haversine, קיים
  ב-`geo.util`). משימות עם מועד לא זזות.

## בדיקות

- יחידה: נרמול טלפון, יצירה/אימות/פקיעה של טוקן, חישובי רווח (Decimal), nearest-neighbor, due-list.
- אינטגרציה (Postgres אמיתי): קישור של טננט A לא פותח נתונים של B; טוקן שפג/בוטל → 404;
  אישור הצעה כפול → משימה אחת; `lastServicedAt` מתעדכן בסגירה; RLS על כל הטבלאות החדשות.
- מדיניות נתיבים: כל נתיב ציבורי `@Public()` מפורש (בדיקת `route-policies.spec.ts`).

## מחוץ להיקף

שליחה אוטומטית (תלויה ב-Meta), תשלום בקישור, חתימה דיגיטלית על הצעה, המרת כתובות בתשלום.
